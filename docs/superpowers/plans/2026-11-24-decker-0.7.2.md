# Decker 0.7.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Decker 0.7.2: About dialog, Core Delay and Sequence, per-action time limits, device-aware nested calls and device-scoped navigation, deck brightness and hotplug for plugins (protocol 5), owner-filtered action fields, and the Counter input crash fix.

**Architecture:** Server changes live in `ActionRunner`/`ActionCall` (timeouts, device in payloads, navigation authorisation), `PluginManager` (new plugin messages, hotplug and brightness broadcasts), `DeviceManager` (multi-listener open/close hooks) and `ScreensaverController` (brightness read/write + listener). The SDK mirrors each protocol addition in a new `_deck.py` module plus small changes to `_actions.py`/`_runtime.py`. Core's two new actions are plain SDK actions in `builtin_plugins/com.decker.core/plugin.py`.

**Tech Stack:** Python 3.14, PyQt6, RPyC, pytest + assertpy, poetry/poe.

**Spec:** `docs/superpowers/specs/2026-11-24-utilities-plugin-design.md` (Part 1). Part 2 has its own plan in `decker-plugins/docs/superpowers/plans/2026-11-24-utilities-plugin.md`.

## Global Constraints

- Version `0.7.2` everywhere Decker reports its version; Core and Blank manifests `"version": "0.7.2"`.
- `PROTOCOL_VERSION = 5`.
- Per-action `timeout`: int seconds, 1–300 (`MAX_CALL_TIMEOUT_S`); absent = today's behaviour (30 s).
- Delay: `com.decker.core.delay`, `seconds` float 0–60, default 1.0, 2 decimals, manifest `timeout` 65, icon `fas:hourglass-half`.
- Sequence: `com.decker.core.sequence`, `step_1`…`step_10` (`action` + `action_params` with `action_field`), `stop_on_error` bool default true, manifest `timeout` 300, icon `fas:list-ol`.
- Deck brightness from plugins clamped to 1–100; stored as the screensaver's normal `brightness`.
- `deck_brightness_changed` goes to every running plugin; `device_connected` on every open, `device_disconnected` on close.
- Quality gates: `poe format`, `poe mypy` (also `mypy --platform win32 .` and `mypy --platform darwin .`), `poe pylint` ≥ 9.0, `poe test` ≥ 85 % coverage. Max 5 args per function, methods < 50 lines, annotate everything.
- Plugin docs in `docs/plugins/` kept in sync with every protocol/manifest change in the same task.
- Work on a branch `feat/0.7.2` (repo is on `main`).

## Review Focus

1. A Sequence whose parent gesture times out — later steps must not keep running past the parent's deadline (each step's timeout is capped by the time left; a step started with ≤ 0 s left is not started). Test in Task 7.
2. Deck reopen during a brightness write fires close+open hooks — plugins must see a consistent `device_connected` afterwards and no exception. Test in Task 4.
3. A plugin sending device-scoped navigation for a device after its action call ended (late thread) — refused, no switch. Test in Task 3.
4. `set_deck_brightness` with a non-int / out-of-range / bool percent, or an unknown device — clamped or error reply, server never raises. Test in Task 5.
5. Sequence step whose `action_params` are invalid for the chosen action — reported as that step's failure naming `step_N`, not a crash. Test in Task 7.
